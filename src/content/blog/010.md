Amazon Web Services (AWS) provides cloud infrastructure and managed services for building, deploying, and scaling applications. Instead of managing every server, database, and networking component, developers can rely on AWS for much of the underlying infrastructure.

AWS offers hundreds of services, but a smaller set appears repeatedly in real applications. The goal is not to memorize the entire catalog. It is to recognize what each service is responsible for and understand how they fit together.

## Compute and Containers

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Compute/48/Arch_Amazon-EC2_48.svg" alt="Amazon EC2 icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> Amazon EC2

Virtual servers with configurable operating systems, compute resources, and networking. EC2 provides flexibility, but the application team is responsible for maintaining its instances.

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Compute/48/Arch_AWS-Lambda_48.svg" alt="AWS Lambda icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> AWS Lambda

Runs functions in response to events, such as an API request or a queue message, without managing servers. It works well for short-lived, event-driven processing.

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Containers/48/Arch_Amazon-Elastic-Container-Service_48.svg" alt="Amazon ECS icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> Amazon ECS

Orchestrates containerized applications, including scheduling tasks, maintaining services, and scaling deployments.

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Containers/48/Arch_AWS-Fargate_48.svg" alt="AWS Fargate icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> AWS Fargate

Runs containers for services like ECS without requiring you to manage the underlying servers.

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Containers/48/Arch_Amazon-Elastic-Container-Registry_48.svg" alt="Amazon ECR icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> Amazon ECR

Stores and versions container images so services such as ECS can pull consistent application builds.

## Storage and Databases

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Storage/48/Arch_Amazon-Simple-Storage-Service_48.svg" alt="Amazon S3 icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> Amazon S3

Object storage for documents, images, backups, logs, and other files. Objects are organized into buckets and accessed through APIs.

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Database/48/Arch_Amazon-DynamoDB_48.svg" alt="Amazon DynamoDB icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> Amazon DynamoDB

A fully managed NoSQL database designed for low-latency access at scale. Useful for application state, sessions, and metadata when access patterns are well understood.

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Database/48/Arch_Amazon-RDS_48.svg" alt="Amazon RDS icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> Amazon RDS

Manages relational databases such as PostgreSQL and MySQL, handling much of the operational work while applications use SQL.

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Database/48/Arch_Amazon-ElastiCache_48.svg" alt="Amazon ElastiCache icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> Amazon ElastiCache

Managed in-memory caching that reduces repeated database queries and speeds up access to frequently requested data.

## Networking and APIs

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Networking-Content-Delivery/48/Arch_Amazon-API-Gateway_48.svg" alt="Amazon API Gateway icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> Amazon API Gateway

Provides an entry point for HTTP, REST, and WebSocket APIs, with features such as authorization, throttling, and routing to backend services.

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Networking-Content-Delivery/48/Arch_Elastic-Load-Balancing_48.svg" alt="Elastic Load Balancing icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> Elastic Load Balancing

Distributes incoming traffic across application targets. An Application Load Balancer can route HTTP requests to ECS tasks or EC2 instances.

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Networking-Content-Delivery/48/Arch_Amazon-Route-53_48.svg" alt="Amazon Route 53 icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> Amazon Route 53

DNS service that connects a domain name to the application’s endpoints and supports routing and health checks.

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Networking-Content-Delivery/48/Arch_Amazon-CloudFront_48.svg" alt="Amazon CloudFront icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> Amazon CloudFront

A content delivery network that caches content closer to users, improving delivery speed for assets and certain dynamic workloads.

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Networking-Content-Delivery/48/Arch_Amazon-Virtual-Private-Cloud_48.svg" alt="Amazon VPC icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> Amazon VPC

Defines an isolated virtual network for AWS resources, including subnets, routing, and network access controls.

## Messaging and Event-Driven Systems

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Application-Integration/48/Arch_Amazon-Simple-Notification-Service_48.svg" alt="Amazon SNS icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> Amazon SNS

A publish-subscribe service that sends an event to multiple subscribers. Useful when different parts of an application must react to the same event.

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Application-Integration/48/Arch_Amazon-Simple-Queue-Service_48.svg" alt="Amazon SQS icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> Amazon SQS

Stores messages for asynchronous processing. Queues decouple producers from consumers, buffer traffic spikes, and support retries and dead-letter queues.

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Application-Integration/48/Arch_Amazon-EventBridge_48.svg" alt="Amazon EventBridge icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> Amazon EventBridge

Routes events between systems according to rules, enabling loosely coupled event-driven architectures.

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Application-Integration/48/Arch_AWS-Step-Functions_48.svg" alt="AWS Step Functions icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> AWS Step Functions

Coordinates multi-step workflows across services, tracking state and handling branches, retries, and failures.

## Security, Monitoring, and Deployment

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Security-Identity-Compliance/48/Arch_AWS-Identity-and-Access-Management_48.svg" alt="AWS IAM icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> AWS IAM

Controls which identities and services can perform actions on specific AWS resources. Policies and roles help enforce least-privilege access.

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Security-Identity-Compliance/48/Arch_AWS-Secrets-Manager_48.svg" alt="AWS Secrets Manager icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> AWS Secrets Manager

Stores credentials, tokens, and other secrets securely so applications can retrieve them at runtime instead of embedding them in code.

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Management-Governance/48/Arch_Amazon-CloudWatch_48.svg" alt="Amazon CloudWatch icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> Amazon CloudWatch

Collects metrics, logs, and alarms to monitor production systems and investigate failures.

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Developer-Tools/48/Arch_AWS-Cloud-Development-Kit_48.svg" alt="AWS CDK icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> AWS CDK

Defines AWS infrastructure in languages such as TypeScript or Python, making deployments reproducible and version-controlled.

## AI and Agent Infrastructure

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Artificial-Intelligence/48/Arch_Amazon-Bedrock_48.svg" alt="Amazon Bedrock icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> Amazon Bedrock

Offers managed access to foundation models through APIs for tasks such as summarization and other generative AI features.

### <img src="https://raw.githubusercontent.com/icacho-dev/aws-architecture-icons/main/Architecture-Service-Icons_02072025/Arch_Artificial-Intelligence/48/Arch_Amazon-Bedrock-AgentCore_48.svg" alt="Amazon Bedrock AgentCore Gateway icon" width="36" height="36" style="vertical-align:middle; margin-right:0.5rem" loading="lazy" /> Amazon Bedrock AgentCore Gateway

Exposes approved APIs and Lambda-based tools to AI agents through a managed gateway. This helps organize agent tool access and apply authentication and security controls.

## Example: An AI-Powered Document Processing App

Imagine an application where users upload documents, receive AI-generated summaries, and ask questions about their files. Here's one way to build it with AWS:

![Simplified AWS architecture for an AI document processing application](/aws-document-processing.svg)

1. **Receive requests.** Route 53 resolves the domain and CloudFront serves frontend assets. API Gateway sends API requests to a backend running on Lambda or ECS Fargate.
2. **Store files and state.** The backend puts uploaded documents into S3 and tracks ownership, IDs, and processing status in DynamoDB.
3. **Process uploads asynchronously.** After an upload, the backend publishes an event to SNS. SNS sends it to an SQS processing queue, where a Lambda worker can consume it when ready. A separate queue could receive audit or notification events.
4. **Generate a summary.** The worker extracts text and calls a model through Amazon Bedrock. It saves the result to S3 or DynamoDB, then marks the document as processed.
5. **Add agent capabilities.** An AI agent can access approved tools through AgentCore Gateway—for example, retrieving document metadata or looking up a saved summary. Tool permissions remain restricted.
6. **Operate the application.** IAM limits resource access, Secrets Manager holds credentials, CloudWatch collects logs and metrics, and CDK defines infrastructure as code.

This is an illustrative architecture, not a requirement to use every AWS service. For a small prototype, S3, Lambda, DynamoDB, and API Gateway may be enough. Messaging, container orchestration, and additional security layers become useful as the application grows.

## Conclusion

AWS services separate responsibilities: compute runs code, databases store state, queues manage asynchronous work, and networking connects users to applications. Understanding these building blocks—and the tradeoffs between them—is more useful than reaching for as many services as possible.
